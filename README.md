# Финансист 1.5

Личное приложение PWA для Android и компьютера. Без банковских API, регистрации, QR и фото чеков. Внешних зависимостей и платных сервисов нет.

## Запуск

Требуется Node.js 20 или новее. В папке проекта:

```powershell
node server.mjs
```

Открыть http://localhost:4173. Проверки расчётов: `node --test tests/*.test.mjs`.

## Android

Распакуй архив в папку `financier` на телефоне и укажи её в Simple HTTP Server. Запусти сервер и открой в Chrome **http://localhost:8080/** на том же телефоне (порт должен совпадать с настройками сервера). Установи приложение / добавь его на главный экран. После первой полной загрузки приложение сохраняет файлы для работы без сервера. Сервер понадобится снова для загрузки обновлений или если браузер удалил кэш.

Адрес `http://192.168.…` из окна сервера отличается от `localhost`: обычный сетевой HTTP не даёт полноценного PWA-офлайн-режима. Альтернатива — статический HTTPS-хостинг. Встроенный `server.mjs` предназначен для компьютера и слушает только 127.0.0.1.

### Обновление установленной версии

1. В старом приложении: Настройки → Скачать копию. Сохрани JSON отдельно от папки приложения.
2. Замени файлы в прежней папке содержимым нового архива. Копируй все файлы: в 1.5 добавлены `timeline-model.js`, `timeline.js` и `timeline.css`.
3. Запусти Simple HTTP Server, открой **прежний адрес с прежним портом в прежнем браузере** и обнови страницу. При необходимости обнови её ещё раз после загрузки.
4. В новой версии есть кнопка Настройки → Проверить обновление. Проверь свои остатки и операции, затем сервер снова можно остановить.

Не очищай данные сайта: там находятся твои записи. Если сменился адрес или браузер, восстанови сохранённый JSON через Настройки → Восстановить. Старые копии поддерживаются.

## Возможности

- Курьерка: одна запись — одна поездка, внутри число выдач (быстрые кнопки 1–7). Пакеты больше не запрашиваются. Время взятия — дата и время, по умолчанию момент добавления; для Магнита при вводе после доставки уточни его вручную. У старых записей время не выдумывается: «Время не указано». Старые количества заказов считаются выдачами; старые смены без разбивки не получают вымышленного числа поездок. Пустая стоимость поездки допустима и помечает итог как неполный.
- Единый календарь денег, неделя/месяц. Наложенные столбцы: широкий зелёный доход, узкий красный расход, общий масштаб периода. Режим «Получено» использует поступления всех категорий; «Заработано» — смены, расчётки и чай по рабочему дню, прочие доходы по дню поступления. Оценки штрихуются. Фактическая выплата курьерки в режиме заработка повторно не добавляется. Плановые платежи и предполагаемая выплата отмечаются отдельно от столбцов факта. Нажатие на день показывает операции, смены и планы.
- Запланированные покупки вместе с регулярными платежами: «Купил» с уточнением суммы и счёта, «Перенести», «Отменить». Будущая дата обычного расхода автоматически создаёт план, а не движение денег. Просроченный план ждёт решения. При подтверждении резерв заменяется фактическим расходом. Планы можно открыть через «Ещё → Покупки и платежи».
- Прогноз остатка на 30 дней: имеющиеся деньги после текущих резервов, учтённые планы/рассрочки/долги; отдельно сценарий с известной ожидаемой курьерской выплатой в предполагаемый ближайший четверг. Новые будущие смены не прогнозируются. Налог с ожидаемого X5 вычитается по настройке; неизвестные суммы отмечаются. Если есть выплаты без привязки к расчёткам, сценарий выключен для защиты от повторного учёта — требуется сверить выплаты и расчётки. Просроченные обязательства включены сегодня.
- Итог месяца: доходы, расходы, разница, чистые переводы в накопления, погашения основного долга, остатки счетов, неоплаченные расчётки и заработок без расчётки. Текущий и неотмеченный полным месяц имеют соответствующую отметку. Остатки прошлого месяца рассчитываются из текущей базы и истории; исправление начального остатка без истории влияет на них.
- Повторное нажатие сохранения в одном окне не создаёт вторую запись. Ошибка проверки снимает блокировку, чтобы исправить ввод.
- Товары: отдельно сумма позиции и цена за единицу. Изменение одного поля пересчитывает второе; изменение количества опирается на последнее изменённое поле. Общая сумма покупки считается по позициям, если не была введена вручную. При расхождении есть кнопка «Взять сумму товаров».
- Фильтры операций спрятаны под лупу: период, категория, важность и поиск. Отметка показывает применение фильтров, есть сброс. Выбор сохраняется при переходах между разделами; при новом запуске показаны все операции за всё время.
- Редактирование счёта показывает текущий остаток. Изменение можно записать отдельной корректировкой в истории или применить без истории. Корректировки не попадают в доходы, расходы или налоговый резерв. Они доступны для изменения в истории.
- Незавершённая операция сохраняется локальным черновиком, включая товары и дополнительные поля; кнопка новой операции продолжает черновик после закрытия или перезагрузки. После сохранения черновик очищается. Один черновик на приложение; начало другого ввода с явными параметрами может заменить его.
- Числовые поля открывают встроенный калькулятор с крупными кнопками: +, −, ×, ÷, скобки, десятичная запятая. Кнопка «Готово» переносит результат в поле. Для очистки необязательного значения — C, затем «Готово». Количество заказов/платежей принимает только целое число; быстрые кнопки заказов 1–7 сохраняются.
- Выбор категории: основная категория, затем её название как общая категория и список подкатегорий. Такой выбор доступен также у товаров.
- Автоматические локальные копии предыдущего состояния при изменениях: до 14 дневных и 5 последних версий, без напоминаний. Настройки → Открыть копии: скачать или восстановить. Копии находятся в этом же браузере и удаляются при очистке данных сайта. При нехватке памяти приоритет у текущих данных; старые копии могут быть освобождены. JSON-экспорт остаётся для внешнего хранения и переноса. Автоматического сохранения в папку телефона или облако нет.
- Быстрые операции: свои кнопки расхода или дохода со счётом, категорией, важностью и необязательной суммой. При использовании достаточно ввести сумму; остальные поля можно раскрыть.
- Регулярные платежи: каждую неделю, две недели или месяц, с необязательной конечной датой. Планы создаются при загрузке и сохранении данных на 120 дней вперёд (или до более поздней даты следующего дохода). Оплата вручную записывает расход. Изменение или приостановка затрагивает неоплаченные даты после сегодня; сегодняшние, просроченные и оплаченные сохраняются. Удалённый отдельный план не создаётся заново.
- Календарь заработка: неделя или месяц, фильтр X5/Магнит, подробности дня. Оценки смен без расчётки показаны как ожидаемые; расчётка заменяет оценки своего периода. Подтверждённая сумма распределяется по дням пропорционально оценкам смен — это расчётное распределение. Без оценок сумма показана в последний день расчётного периода. Чай отдельно, фактические выплаты не прибавляются повторно.
- На главной: свободные деньги до следующего дохода, ориентир на день и раскрываемый расчёт обязательств. Ожидаемый заработок не увеличивает свободный остаток.
- Светлая, тёмная и автоматическая тема по настройке телефона. Зелёный акцент, янтарные ожидаемые суммы; выбор сохраняется в резервной копии.
- Ручные доходы, расходы, переводы; изменение и удаление операций.
- Карты, наличные, накопительные счета, цели; один накопительный счёт на цель.
- Отдельный экран категорий доходов и расходов: основные категории раскрываются нажатием. Свои подкатегории, переименование, скрытие и удаление с переносом истории. При вводе операции — основная категория, затем общая категория или подкатегория. Суммы подкатегорий входят в основную категорию без повторного учёта. Можно задать общий лимит и отдельные лимиты подкатегорий.
- Важность покупки: не оценено, не нужно, хотелось, нужно, обязательно.
- Отдельные товары с количеством, единицами, категориями и важностью; динамика цены по совпадающим названиям и единицам в выбранном периоде. Сумма позиции — после скидки; сумму и цену за единицу можно вводить в обе стороны. Упаковки разного объёма нужно различать в названии.
- Долги в обе стороны, выдача/получение и частичные погашения. Старый долг можно завести без движения денег. Рассрочки: равные платежи по числу, раз в неделю / две недели / месяц, ручное изменение дат и сумм. Погашения распределяются начиная с самого раннего платежа.
- Календарные напоминания: отдельные события Google Calendar на телефоне или экспорт всего графика в `.ics`. Проверь уведомления в календаре; поддержка сигналов из `.ics` зависит от календаря. Импорт `.ics` в Google Calendar выполняется в веб-версии на компьютере. Приложение не синхронизирует оплаты и изменения графика с календарём.
- Курьерка: начать смену X5 или Магнита; крупная кнопка заказа, клавиатура 1–7 выдач и «Другое», время взятия и примерная общая оплата. В X5 ввод перед заказом, в Магните после доставки. Общая сумма не умножается на число заказов. Доставки можно менять и убирать из активной или завершённой смены. Смена сохраняется при закрытии приложения, можно исправить время начала и завершения. Одновременно допустима одна смена каждого сервиса.
- Чаевые записываются сразу на выбранную карту или наличный счёт как отдельный доход, связанный со сменой. Исправление чаевых — через операции. В итогах смены отдельно заработок, чай, предварительный налог, время, поездки и выдачи. Оценка заказа не увеличивает баланс. В расчётку и выплату вноси только деньги, которые ещё должен получить, без уже полученного чая.
- Подтверждённая недельная расчётка и фактическая/частичная выплата — отдельные этапы по каждому сервису. Старые смены из 1.1 сохранены в истории и доступны для изменения прежней формы.
- Предварительный налог X5: процент задаётся пользователем, по умолчанию не установлен; можно включить чай в расчёт. Магнит не создаёт дополнительный резерв. Процент сохраняется в новой операции дохода; при изменении настройки старые операции не пересчитываются. Для них процент меняется вручную в операции.
- Резерв налога возникает только на полученные деньги, уменьшает доступную сумму, но не баланс счёта. Оплата налога — обычный расход с выбранным источником дохода и отметкой «Это оплата налога»: резерв уменьшается без двойного вычитания. Кнопка оплаты в настройках только записывает расход, ничего не платит через банк.
- Расход можно вручную связать с категорией дохода для аналитики «получено / вычеты / после вычетов». Транспорт автоматически не относится к курьерке. Налоговая оценка и реально оплаченный налог показываются отдельно.
- Автоматический бюджет — расходы прошлого полного месяца. Чтобы включить его, отметь предыдущий месяц заполненным полностью. До этого показано «Недостаточно информации». Ручные лимиты имеют приоритет. Сравнение текущего месяца с таким же числом дней прошлого, с учётом коротких месяцев; доля расходов относительно всех или только рабочих фактических доходов. «Рабочий доход» настраивается у категории; признак основной категории распространяется на её подкатегории.
- Крупный текст и кнопки, пять разделов в нижнем меню. Бюджет, отчёты, категории и настройки находятся в «Ещё».
- Бюджет, лимиты, будущие платежи, оплата плана через запись расхода.
- Графики по категориям, необходимости и времени.
- JSON-запрос с инструкцией и схемой ответа для выбранной нейросети; проверка и отображение ответа, история отчётов. Запрос включает подкатегории, рассрочки и этапы курьерского дохода.
- JSON-копии данных и восстановление с валидацией.

## Первые действия

1. Добавить свои счета с остатками до первой внесённой операции.
2. Настроить категории и бюджет.
3. Добавлять операции; для товарной аналитики раскрывать отдельные позиции покупки.
4. В отчётах выбрать период, нажать «Собрать отчёт», затем «Запрос нейросети». Подготовить и скопировать JSON.
5. Отправить JSON выбранной нейросети. Вставить полученный JSON через «Вставить ответ».
6. Регулярно скачивать копию в настройках.

## Особенности расчётов

Все денежные суммы — целые копейки; нет ошибок накопления дробных рублей. Переводы и основной долг не попадают в доходы/расходы. Позиции покупки распределяют сумму расхода и не списывают деньги дополнительно. Будущие операции оформляются планами. Резерв накоплений до следующего дохода нужно уменьшать вручную после фактического перевода, поскольку накопительные счета уже исключены из доступных денег. Долг к сроку нельзя также дублировать будущим платежом — он уже зарезервирован.

Доступные деньги: карты и наличные минус неоплаченные планы, платежи рассрочек и обычные долги к сроку до следующего дохода, минус резерв накоплений и неоплаченный налоговый резерв. В курьерском режиме горизонт — ближайший четверг; после записанного поступления в четверг — следующий четверг. Оценки заработка и расчётки не увеличивают доступные деньги. Доходом становится только фактическое поступление. История сумм показывает последние фактические поступления, включая частичные. Налог — предварительная оценка по твоему проценту, не автоматическая расчётка ФНС.

## Ограничения

Нет автоматической синхронизации, банковского импорта, автоматического списания денег, PIN/биометрии или шифрования базы. Данные сохраняются в localStorage отдельно для каждого адреса и браузера; очистка браузера удалит их. Не открывать одновременно в нескольких вкладках для редактирования. Удаление/изменение операции может изменить историю; долг нельзя уменьшить ниже погашенной суммы. Возврат покупки пока корректируется изменением исходного расхода, отдельной операции возврата нет.

Рекомендации нейросети проверяются по структуре, но не гарантируются как верные по смыслу. Графики рассчитывает приложение. Сохранённый AI-отчёт относится к снимку данных на момент запроса. Запрос и резервные копии содержат названия, комментарии и финансовые данные; проверяйте их перед передачей.

Кнопка «Загрузить пример» в настройках заменяет базу вымышленными данными с подтверждением. По умолчанию приложение пустое.
